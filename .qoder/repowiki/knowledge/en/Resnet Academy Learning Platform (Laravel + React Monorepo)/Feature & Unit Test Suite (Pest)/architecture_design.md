Tests are split into two top-level suites: `tests/Feature` for integration-style HTTP and service-layer tests that exercise full request/response cycles and database state, and `tests/Unit` for isolated model, middleware, request validation, and migration tests. Both suites extend a shared `TestCase` base class; Pest configuration in `Pest.php` applies `RefreshDatabase` to all Feature tests via `pest()->extend(TestCase::class)->use(RefreshDatabase::class)->in('Feature')`, while Unit tests run without it. The directory layout mirrors the application domain — e.g., `Feature/Auth`, `Feature/Assessment`, `Feature/Services/Enrolment` map directly onto `App\Http\Controllers`, `App\Services`, etc. A global `fakeImageUpload()` helper in `Pest.php` provides a real PNG `UploadedFile` for image-mime validation tests, avoiding GD dependency issues. Tests use both Pest's function-style `it(...)` DSL and traditional PHPUnit classes (e.g., `CourseSectionEnrolmentTest`) depending on complexity.
