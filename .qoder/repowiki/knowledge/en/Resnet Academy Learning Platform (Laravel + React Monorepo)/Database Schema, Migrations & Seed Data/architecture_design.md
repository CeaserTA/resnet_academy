Organized as a standard Laravel `database/` directory with three sub-packages:
- `migrations/`: chronological, timestamp-prefixed migration files (starting at `0001_01_01_...` for core tables like users/cache/jobs, then domain tables grouped by feature — courses, modules/resources, assignments, evaluations, messaging, forums, payments, course sections/reviews). Each migration is an anonymous class extending `Illuminate\Database\Migrations\Migration`, using `Schema::create` with explicit foreign keys via `foreignId()->constrained(...)` and named indexes (`fk_*`, `idx_*`, `uq_*`). Later migrations add columns or new tables to evolve the schema.
- `factories/`: one `*Factory.php` per Eloquent model in `App\Models`, each extending `Illuminate\Database\Eloquent\Factories\Factory` and providing state methods (e.g. `admin()`, `instructor()`, `student()`, `draft()`) to compose test fixtures.
- `seeders/`: `DatabaseSeeder` orchestrates creation of ~10 rows per entity in a fixed dependency order (users → categories → courses → groups → modules → resources → assignments → evaluations → enrolments → orders/payments → certificates/reviews → messaging/tickets/announcements/forums → notifications/engagement/audit logs), using both factories and direct `Model::create()` calls for entities without factories. A secondary `FeaturedReviewsSeeder` exists for targeted seeding.

Dependency direction is strictly downward: seeders depend on factories and models; factories depend on enums and models; migrations are schema-only and have no runtime dependencies. The module ships with an embedded `database.sqlite` file for quick local setup.
