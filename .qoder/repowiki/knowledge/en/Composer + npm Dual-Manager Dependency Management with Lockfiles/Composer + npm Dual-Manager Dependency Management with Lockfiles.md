## Overview

This repository is a Laravel + React monorepo that manages dependencies through two separate package managers, each with its own manifest and lockfile:

- **Backend (PHP/Laravel)**: Composer (`composer.json` at repo root)
- **Frontend (React/Vite/TypeScript)**: npm (`frontend/package.json`, `frontend/package-lock.json`)

There is no monorepo tool (e.g., Turborepo, Lerna, pnpm workspaces) — the two sides are independent projects co-located under one Git repository.

## Backend: Composer

### Manifest and versioning
- Root `composer.json` declares PHP `^8.2` as the runtime requirement.
- Production dependencies live under `require` (Laravel framework ^12, Sanctum, Socialite, DomPDF, Scramble API docs, AWS S3 Flysystem adapter, Resend email).
- Development-only tools live under `require-dev` (Pest, PHPUnit, Larastan, Pint, Pail, Sail, Mockery, Faker, Breeze).
- Version ranges use caret (`^`) semantics; some packages pin exact versions (e.g., `league/flysystem-aws-s3-v3: 3.0`).

### Lockfile
- `composer.lock` is committed to the repository and contains the full transitive dependency tree with content hash, source URLs, and shasums for every installed package. This pins the backend build to an exact snapshot of all Composer packages.

### Autoloading and discovery
- PSR-4 autoload maps `App\` → `app/`, `Database\Factories\` → `database/factories/`, `Database\Seeders\` → `database/seeders/`.
- Test code autoloads via `autoload-dev` mapping `Tests\` → `tests/`.
- Package auto-discovery runs on post-install hooks (`post-autoload-dump`, `post-update-cmd`, `post-root-package-install`, `post-create-project-cmd`, `pre-package-uninstall`).

### Plugin policy
- `config.allowed-plugins` explicitly whitelists only `pestphp/pest-plugin` and `php-http/discovery`; all other Composer plugins must be explicitly allowed, enforcing a restrictive plugin policy.

### Scripts
- `composer setup` performs a full bootstrap: install deps, copy `.env.example`, generate app key, run migrations, then `npm install` and `npm run build` (bridging both halves).
- `composer dev` concurrently starts the Laravel server, queue listener, log tailer, and Vite dev server.
- `composer test` clears config then runs Pest/PHPUnit.

### Stability
- `minimum-stability: stable` and `prefer-stable: true` prevent accidental installation of pre-release packages.

## Frontend: npm

### Manifest and versioning
- `frontend/package.json` declares production dependencies (React 19, TanStack Query, TipTap editor suite, Radix UI primitives, Axios, Tailwind, Zod, etc.) and development dependencies (Vite, TypeScript, Vitest, Playwright, ESLint, Prettier, Testing Library).
- All versions use caret (`^`) ranges, allowing minor/patch upgrades automatically.

### Lockfile strategy
- `frontend/.npmrc` sets `package-lock=false`, which disables npm's default lockfile generation. However, a `frontend/package-lock.json` file still exists in the repo (likely generated by another tool or manually), so the effective behavior depends on how npm is invoked. The explicit `.npmrc` setting means `npm ci` will not produce a deterministic lockfile unless one is already present.

### Scripts
- `dev`: Vite dev server.
- `build`: TypeScript type-check (`tsc -b`) then Vite production build.
- `test` / `test:watch`: Vitest unit tests.
- `test:e2e*`: Playwright E2E tests.
- `lint`: ESLint.
- `format`: Prettier.
- `preview`: Vite preview of built output.

## Cross-cutting conventions

1. **Separate manifests per language** — PHP dependencies are declared exclusively in root `composer.json`; Node.js dependencies are declared exclusively in `frontend/package.json`. There is no shared workspace configuration.
2. **Lockfiles for reproducibility** — `composer.lock` is committed and authoritative for the backend. The frontend has a `package-lock.json` alongside an `.npmrc` that disables lockfile generation, creating a tension between deterministic installs and the configured behavior.
3. **No vendoring** — Neither side uses vendored copies of third-party code (no `vendor/` committed, no `node_modules/` committed). Dependencies are fetched from public registries (Packagist for Composer, npm registry for Node) at install time.
4. **No private registries** — No `repositories` entries in `composer.json` and no `.npmrc` registry overrides beyond `package-lock=false`. All packages resolve from their default public registries.
5. **Monorepo bootstrap script** — The root `composer setup` script orchestrates both ecosystems in sequence, making Composer the entry point for full project initialization.
